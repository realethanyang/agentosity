## 一、产品定位(一句话)

打工人下班打卡 → 公司按平均下班时间排名 → **只公布前三名** → 把"卷加班"变成"卷早下班"。
副线:**Agent 加班榜(Agentosity)**——证明"公司越 AI-native,人走得越早";升维方向是把"AI-native 程度"做成可测量的数字(详见第八节)。

## 二、核心机制

1. **反转内卷**:排名、攀比、面子这些让人加班的机制,原地反转,逼大家抢着早走;
2. **只公布前三,不公布倒数**:只有正面激励,没有负面羞辱;
3. **私信报排名**:每个打卡者第二天收到自己公司的排名 + "离进前三还差 X 分钟";
4. **每日揭榜仪式**:每天 10:00 揭榜,榜单按类别轮播,天天有悬念。

## 三、核心功能(MVP)

1. **打卡下班**:一键打卡,匿名(设备 ID 标识);
2. **揭榜**:每天 10:00 公布,公开榜只露前三名;
3. **我的排名**:第二天看自己公司排名 + 离前三差距;
4. **补卡**:独立功能,补打卡前一天(选日期 + 填那天下班时间)。

## 四、榜单结构

- **全国总榜**(只露前三)+ **行业 / 城市标签榜**(可点击标签筛选,也露前三);
- 同一套数据切出多个可炫耀的名头;
- 揭榜卡片显示 **3 个数**:今日平均下班 / 昨日平均下班 / 一周平均下班;
- 行业、城市为**标签式(tags)**,一家公司可多个(字节跳动多城市、小米跨汽车+APP 等领域)。

## 五、数据规则

- **打卡周期**:每天 = 凌晨 5:00 ~ 次日 4:59;5:00 前打 = 前一天,5:00 后 = 当天;
- **有效窗口**:只统计 **12:00(中午)之后**的打卡;
- **凌晨 0:00-4:59 打卡**:默认归前一天,打卡时弹提示"这条算作前一天的下班";
- **最小样本**:1 人即可上榜;
- **周末榜**:MVP 不做(主榜只算工作日,周一~周五);
- **远程办公**:按公司城市归属计算。

## 六、登录与身份

- **Supabase Auth,无密码邮箱登录**(不做用户名/密码,不碰密码存储责任):
  - Web:输邮箱 → magic link 或 6 位验证码,Supabase 原生支持;
  - CLI / menu bar app:学 `gh auth login` —— `agentosity login` 拉起浏览器完成验证、回传 token 存本地;浏览器不可用时退化为"输邮箱收 6 位码";
- 打卡用匿名设备 ID(未登录也能打),登录后合并、可跨设备查看"我的排名";
- 管理后台独立于普通用户(管理者身份)。

## 七、公司与后台

- **内置公司名单**:内置一份常见公司名单(几百家知名 + 科技/互联网公司),用户搜索命中即可选;
- **手动创建**:搜不到就允许用户创建(创建后全站可见),也是冷启动数据来源;
- **管理后台**:管理者可查看数据,对**手动创建**的公司进行**合并 / 删除 / 修改**。

## 八、Agentosity —— Agent 加班榜(差异化爆点)

**理念**:Agent 在替你加班,所以你才能早下班;"公司越 AI-native,人走得越早"。
**升维**:Agentosity(agent + -osity,同 luminosity/viscosity 的量纲后缀)= 衡量一个人/组织 AI-native 程度的标尺。人人都自称 AI-native,我们把这个形容词变成可测量的数字——"AI-native is a number now."

### 指标体系(命名已定)

- 基本单位:**agent-hours**(机时,刻意对仗 man-hours / GPU-hours);
- **Session Hours**:在岗时长(进程生命周期墙钟口径,诚实底座);
- **Active Agent-Hours**:活跃时长(探针过滤后的干活时间,**榜单主指标**);
- **DAA / MAA**(Daily/Monthly Active Agents):活跃 Agent 数(接上百度李彦宏在推的 DAA 话语);
- **Agent Overtime**:人类下班后的 agent-hours(情绪担当,"人类零加班,Agent 加班 200 小时");
- **Agent Leverage** = agent-hours ÷ human-hours(AI-native 指数,王牌比值);
- **Agentosity Score**:以上指标合成的个人/团队/公司总分。

### 采集架构(核心决策:不让模型打卡,让 server 感知生命周期)

原方案"靠 prompt 让模型调 agent_start/agent_end"已废弃——会话结束时模型不会被唤醒,agent_end 必然丢;考勤不能靠被考勤者自觉。

1. **本地 stdio MCP 进程 = 考勤机(主路径)**:用户在 harness 的 MCP 配置里登记 `npx agentosity ...`,harness 启动会话时自动 spawn、关闭时自动杀。initialize 握手 = start(从 clientInfo 识别 harness/agent_type,零 prompt、模型一个工具都不用调);stdin EOF / SIGTERM = end(退出前抢发"遗言"上报)。**心跳为准、遗言为辅**:进程每 1-2 分钟心跳一次,服务端以最后心跳结算时长(误差 ≤1 分钟),异常退出(SIGKILL/断电)自动兜底,不产生悬挂 session。只依赖 MCP 公共协议,Claude Code / Codex CLI / Cursor / Gemini CLI / Cline 等全兼容,和用户用什么 harness 解耦。资源:仅心跳 HTTP,CPU≈0,内存 30-50MB(远期可 Bun 编译单二进制压到几 MB)。
2. **活跃度探针(区分"在岗"与"干活",三信号取并集)**:
   - **会话文件 mtime**:主流 harness 都为"恢复会话"把内容实时持久化本地(Claude Code:~/.claude/projects/\<项目slug\>/\<session\>.jsonl;Codex:~/.codex/sessions/;Gemini CLI、Aider 类似)。写盘 = 活跃心跳。**只 stat 不 read**,开源自证不碰内容;
   - **尾巴状态**:jsonl 最后一条若是未等到 tool_result 的 tool_use → 工具在途 = 正在干活(解决"15 分钟构建期间文件不动被误判 idle"——长程任务是 Agent 的未来,这条必须有),设 2 小时级疯狂上限防异常;
   - **进程树**:harness 有无除我们外的活跃子进程(每 30 秒 ps 一次,长工具调用几乎都 spawn 子进程,harness 无关的通用信号);
   - 定位当前会话文件的启发式:进程 cwd = 项目目录 + 文件创建时间 ≈ 进程启动时间;同项目并发多开可能张冠李戴,但 session 数量与公司级总量不受影响;
   - **探针注册表**:clientInfo 认出 harness → 挂对应探针;认不出或探针失效(路径非官方 API,会悄悄变)→ **显式报告降级**回 Session Hours 口径,绝不默默给错数。社区可按 harness 提交几十行的探针适配(开源传播点);
   - 误差方向刻意偏保守:轻微低估比虚高可信。
3. **远程 MCP(Vercel 函数)= 零安装 demo 入口(降级路径)**:只在工具被调用时可见,时长靠"任何调用刷新 last_seen + 超时结算"兜底,数据精度低,仅作现场演示与尝鲜。
4. **远期"精确模式"**:Claude Code 原生 OpenTelemetry(用户配 OTLP endpoint),官方接口不怕升级坏,进开源 roadmap v2。

### 产品形态(多端,核心逻辑收进共享库,客户端皆薄壳)

- **CLI(一等公民,跨平台)**:`npx agentosity` —— init(配公司+写 MCP 配置)/ status(今日数据)/ clockout(人类打卡)/ login。mac / Windows / Linux 行为完全一致,**Windows 用户全功能不缺席**;
- **macOS menu bar app**(SwiftUI MenuBarExtra,原生几 MB):图标徽标实时显示活跃 agent 数(常驻活广告),popover 展示今日 agent-hours 等 + **一键人类打卡**(高频动作零摩擦);app 兼任探针宿主。**不用 Electron**(轻量人设不能崩);
- **Windows 托盘版**:进 roadmap(Win11 托盘默认折叠、存在感弱,优先级低;若三个月内必须有,客户端选型倒向 Tauri v2 一份代码双平台);
- **Web**:看榜、分享、管理后台——"打卡"高频动作交给菜单栏/CLI,Web 降级为展示场。

### 竞品结论(2026-08 调研,无直接撞车)

- 最近邻居是**个人向** Claude Code 使用排行榜:claudeusage.com(cost/hours/tokens + 公开榜)、ccgather.com(个人+国家维度)、ccusage(知名本地 CLI 统计,无榜)。均无公司维度、无"Agent 替你加班"叙事;它们全靠读本地会话文件,反而验证探针路线是通行做法;
- AgentOps/Langfuse 是企业可观测性工具;Lean AI Native Leaderboard 排人均营收、人工审核;百度在推 DAA 概念但无人真测——"大佬在喊,我们在测"可以蹭;
- demo 话术(主动划清界限):"个人晒 token 消耗的榜已经有了,我们做反过来的事——不比谁用得多,比哪家公司的 Agent 把加班扛走了、人下班最早。"

**demo 钩子**:人类 6 点下班 → 大屏上公司 Agent 计数器夜里继续涨 → 次日榜显示"你们公司 22:00 还有 3 个 Agent 在上班";可加"在岗 5 小时、实际干活 3.2 小时"细节秀数据可信度。

## 十、技术方案

### 技术栈
| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | **Next.js**(或 Vite+React)+ **Tailwind**,移动优先 PWA | 手机扫码即打卡、零安装、可分享链接 |
| 后端/DB | **Supabase**(Postgres + Auth 无密码邮箱 + Realtime) | 匿名身份、实时订阅(打卡→大屏实时刷新)、开箱即用 |
| 部署 | **Vercel** | 前后端一起发,含远程 MCP 函数 |
| Agent 采集 | **Node CLI + 本地 stdio MCP + 探针**(npm 包 `agentosity`) | 跨平台、零维护、生命周期即考勤(详见第八节) |
| mac 客户端 | **SwiftUI MenuBarExtra** | 原生轻量,菜单栏常驻 + 一键打卡;不用 Electron |
| 视觉 | **Neo Brutalism**(粗边框+硬阴影+高饱和色块+粗体大字) | 反精致戏谑气质,与主题契合,纯 CSS 可做 |

### 数据模型
```sql
-- 公司
companies(
  id uuid PK,
  name text,
  industry_tags text[],   -- 行业标签(可多个)
  city_tags text[],       -- 城市标签(可多个)
  source text,            -- 'builtin' | 'user_created'
  created_at timestamptz
)

-- 打卡记录
checkins(
  id uuid PK,
  company_id uuid FK,
  user_token text,        -- 匿名设备 ID / 登录用户 ID
  clocked_at timestamptz, -- 实际打卡时间
  day_key date,           -- 按 5:00 分界算好的归属日
  backfill bool,          -- 是否补卡
  created_at timestamptz
)

-- Agent 会话(生命周期 + 心跳 + 活跃度)
agent_sessions(
  id uuid PK,
  company_id uuid FK,
  user_token text,          -- 匿名设备 ID / 登录用户 ID
  harness text,             -- claude-code / codex / gemini-cli / ...(来自 clientInfo)
  started_at timestamptz,   -- initialize 握手时间
  last_heartbeat_at timestamptz,  -- 心跳为准:事实上的结束时间
  ended_at timestamptz,     -- 显式"遗言"上报(可空,有则更精确)
  active_seconds int,       -- 探针算出的活跃时长(Active Agent-Hours 来源)
  probe text,               -- 'file-mtime' | 'none'(降级口径要可见)
  created_at timestamptz
)

-- 用户(可选,Supabase Auth 自带 users 表)
```

### 排名算法
- **日榜**:某公司当天所有有效打卡(12:00 后)时间的算术平均(转分钟计算,再转回 HH:MM),带打卡人数;
- **周榜**:当周所有有效打卡时间的算术平均;
- 同分比打卡人数(人多排前);
- 展示时永远带"平均下班时间 + 打卡人数"两个数。

### Agent 上报的两条路(定位与初稿相比已反转,详见第八节)
- **主路径**:本地 `npx agentosity`(stdio MCP 生命周期 + 心跳 + 活跃度探针)→ `/api/agent/*` API,数据真实;
- **demo 快捷入口**:远程 MCP(Vercel 函数),零安装但精度低,靠"任何调用刷新 last_seen + 超时结算"兜底。
